# 리뷰와 문서 기준 정합성

## 읽을 기준

`AGENTS.md`와 `README.md`에서 문서 책임·현재 브랜치 규칙을 확인한다. 작업은 저장소 루트 기준으로 기록하고 개인 기기의 절대 경로·비밀값을 남기지 않는다. PR 작성·커밋 형식은 기존 스킬을 참조하되 작업 권한을 새로 만들지 않는다.

## 이력 재구성

- 원격을 갱신하고 base/head SHA, 열린 PR·병합 시각을 확인한다. PR 번호 순서는 병합 순서가 아니다. commit authored/committed 시각, 리뷰 제출 시각, 댓글 생성·수정 시각을 구분한다.
- 일반 댓글, 리뷰 본문, inline 스레드와 작성자의 후속 답변을 함께 읽는다. inline 답글의 `in_reply_to_id`는 후속 댓글이 아닌 최초 댓글을 가리킬 수 있다. 사용자 답글 이후 새 질문이 있는지 확인한다. 읽기만 요청받으면 게시하지 않는다.
- 이전 작업 브랜치·평가 기록을 최신 main 또는 실제 배포로 취급하지 않는다. 현재 결정, 구현 commit, 운영에서 확인한 버전, 측정 입력·환경은 별도 근거다.
- 각 질문·제안·약속을 결정됨, 확인 필요, 구현됨, 검증됨으로 구분한다. 질문에 대한 동의가 구체적 구현 정책까지 확정했다는 뜻은 아니다.

## 반영 위치

| 내용 | 기준 위치 |
| --- | --- |
| 제품 범위 | project/prd.md |
| 현재 담당·상태·확인 시점 | project/project-plan.md의 기존 미결 표 |
| 결정 내용과 변경 근거 | project/mvp-review.md의 해당 항목과 결정 기록 |
| 기술 선택·실행·판정·화면 | design의 해당 기준 문서 |
| 실험 조건·관측 결과·한계 | evaluations |
| 배포 명령·API 계약·운영 상태 | be의 해당 문서에 링크 |

- 기존 미결 표를 갱신한다. 날짜별 후속 표나 별도 완료 관리표를 만들지 않는다. 담당·상태·확인 시점·근거는 서로 다른 열로 둔다. 사용 조건·고지·데이터 취급처럼 독립적으로 완료되는 일은 따로 추적한다.
- 현재 기준 문서는 본문과 해당 행을 직접 갱신한다. 오래된 기준을 그대로 둔 채 하단에 “최신 내용 우선” 절을 추가해 해결하지 않는다. 변경 이력은 결정 기록, 과거 실측은 평가 문서에 둔다.
- 백엔드 작업 로그에 이미 실측이 있는지 확인한다. 코드 테스트, 실모델 가상 사례, 실영상·배포 검수를 구분하고 누락된 commit·URL·장비는 미기록으로 적는다. 실험하지 않은 수치·원인·일반화 결론을 만들지 않는다.
- 약속한 문서 링크는 실제 파일·절로 연결한다. 기록이 없으면 없다고 쓰고 기존 미결 표에 추가한다. 답글 게시와 약속 이행은 서로 다른 완료 조건이다.

## 충돌과 검증

최신 main에 병합된 결정을 보존해 충돌을 해결한다. 한쪽 파일 전체를 선택했다면 다른 쪽 리뷰 약속을 원문과 대조해 모두 재반영한다. 다른 열린 PR의 변경을 무단으로 합의·병합하지 않고 의존성과 남은 검토를 밝힌다.

`python3 .agents/skills/reconcile-docs/scripts/check_docs.py --base origin/main`으로 변경 Markdown 전체의 로컬 파일·절 링크, 연속 빈 줄, 표 열 수, 충돌 표시를 검사한다. 이어 `git diff --check`와 의미 검토를 수행한다. 외부 링크는 해당 원격 commit에서 열리는지 별도로 확인한다. 스크립트 통과는 내용 정확성·실행 품질을 보장하지 않는다.

최종 보고에는 반영한 약속, 미결 항목 위치, 검증 범위, commit·PR·원격 반영 상태를 적는다. 댓글 게시, PR 병합, 공개 접근 변경은 각각 사용자 요청 범위 안에서만 한다. 문서 반영을 끝내기 전에 스레드가 해결됐다고 표시하지 않는다.
