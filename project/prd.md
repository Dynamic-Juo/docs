# Conan AI (가제) 제품 요구사항

- 상태: `Draft`
- 기획 담당: 조정준 팀장
- 관련 문서: [킥오프 회의록](../meetings/2026-09-03-kickoff.md), [AI 파이프라인](../design/ai-pipeline.md)

## 문서의 기준

서비스 구상과 1차 기획·기술 조사 자료를 바탕으로 구체화하여 작성했으며, 기획 검토에 따라 내용을 갱신 중이다. AI 모델 선정과 성능·신뢰도 검증은 나정균 팀원이 별도로 진행 중이며, 결과에 따라 관련 요구사항을 보완한다.

요구사항에는 현재 결정 상태와 추가 협의할 내용을 기록한다. `미정`은 결정되지 않은 항목, `보류`는 논의를 미루기로 한 항목, `상세 협의 필요`는 구체적인 범위나 방식을 논의할 항목이다. 문제·사용자·범위와 구현에 관한 가정은 [프로젝트 가정](assumptions.md)에서 구분해 관리하며, 이 문서는 구체화하는 동안 `Draft`로 관리한다.

## 문제와 서비스 목적

기본 방향은 영상 URL을 입력하면 딥페이크 등 미디어 조작 가능성과 영상 속 주장의 사실성을 분석해 알려주는 서비스다. 고령층이 의심스러운 영상 정보를 판단할 때 도움을 주는 것을 목적으로 한다.

서비스를 제안한 배경과 영상 정보 판별의 어려움에 관한 전제는 [프로젝트 가정](assumptions.md#a-01-영상-정보-판별의-어려움)에 기록한다.

## 목표 사용자와 이용 흐름

부모와 자녀 모두 직접 사용할 수 있다. 누가 사용하든 영상 URL을 입력하고 분석 결과를 확인하는 흐름은 같다. 기술에 익숙하지 않은 사용자도 이해할 수 있는 단순한 사용 흐름을 지향한다.

서비스 이용 수요와 자녀를 통한 유입 가능성은 [프로젝트 가정](assumptions.md#a-02-서비스-이용과-유입)에 기록한다.

자녀가 직접 사용하거나 부모에게 소개할 수 있지만, 부모에게 소개하는 것을 서비스 사용의 필수 단계로 두지 않는다.

## 핵심 분석 경계

미디어 조작 가능성과 주장 사실성은 구분해서 제공한다. 실제 영상에도 허위 주장이 포함될 수 있고, AI로 생성된 영상의 발언이 사실일 수도 있으므로 두 결과를 하나의 진위 판정으로 취급하지 않는다.

두 분석 결과는 비슷한 비중으로 제공하되, 주장 사실성 검증을 우선한다. 딥페이크 영상에도 사실인 정보가 포함될 수 있지만, 영상 속 정보가 거짓이면 딥페이크 여부와 관계없이 사용자의 판단에 직접 영향을 줄 수 있기 때문이다.

| 분석 | 기본 방향 | 추가 확인 |
| --- | --- | --- |
| 미디어 조작 탐지 | 얼굴 합성·변형과 영상 전체가 AI로 생성된 경우의 조작 가능성을 분석한다. | 음성 합성 탐지는 MVP에서 제외한다. 유형별 탐지 모델과 판정 기준은 검증이 필요하다. |
| 주장 사실성 검증 | 주제를 제한하지 않고 검증 가능한 주장을 모두 외부 근거와 비교한다. | 근거 선택과 판정은 [주장 근거 선택과 판정 정책](../design/evidence-policy.md)을 따른다. 검색·판정 기술은 추가 검증이 필요하다. |

## 사용자 시나리오

부모와 자녀에게 공통으로 적용되는 기본 흐름이다.

1. 사용자가 확인하고 싶은 영상의 URL을 입력한다.
2. 서비스가 영상을 분석한다.
3. 사용자가 미디어 조작 가능성과 주장 사실성 결과를 확인한다.
4. 사용자가 관련 발언 위치와 근거를 확인한다.

사용자는 영상의 공유 기능으로 링크를 복사한 뒤 서비스의 URL 입력란에 붙여넣는다.

## 제공 형태

MVP는 모바일과 PC 브라우저에서 사용하는 반응형 웹으로 제공한다. Web App Manifest와 앱 아이콘을 추가해 지원 브라우저에서 홈 화면이나 앱 목록에 설치할 수 있는 PWA로 구성한다. 설치 가능 조건은 [MDN PWA 설치 기준](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable)을 참고한다.

영상 수집, 모델 분석과 근거 검색은 서버에서 처리하므로 네트워크 연결이 있을 때만 분석 기능을 제공한다. 오프라인 실행, 백그라운드 동기화, 푸시 알림과 앱스토어 배포는 MVP에서 제외한다.

설치 가능한 환경에는 앱 안에서 설치 진입점을 제공한다. Chromium 계열 브라우저에서는 브라우저 설치 창을 호출하고, iPhone과 iPad에서는 `공유` 메뉴의 `홈 화면에 추가` 절차를 안내한다. 이미 설치된 환경이나 설치를 지원하지 않는 환경에는 설치 진입점을 표시하지 않는다. 설치 창 호출에 사용하는 `beforeinstallprompt`는 Chromium 계열에서만 지원되므로, iOS에서는 별도 안내 화면을 사용한다.

서비스 워커를 이용한 오프라인 캐시, 캐시 버전 관리, 새 버전 감지와 업데이트 알림은 구현하지 않는다. 배포된 변경 사항은 설치형 웹을 다시 실행하거나 페이지를 새로고침할 때 일반 웹과 같은 방식으로 불러온다.

## 요구사항 초안

| 번호 | 내용 | 상태 및 협의할 내용 |
| --- | --- | --- |
| R-01 | 주 사용 언어가 한국어이고 공개 상태가 `public`인 YouTube Shorts URL을 입력받는다. | 일부 공개·비공개·연령 제한 영상은 제외한다. YouTube가 Shorts로 분류한 영상은 [YouTube 공식 기준](https://support.google.com/youtube/answer/15424877)에 따라 현재 최대 3분까지 지원한다. |
| R-02 | 미디어 조작 가능성과 주장 사실성 결과를 분리해 보여준다. | 기본 방향 확정 |
| R-03 | 주제를 제한하지 않고 영상에서 검증 가능한 주장을 모두 추출해 외부 근거와 비교한다. | 같은 의미의 주장은 하나로 합치고 언급 위치를 보관한다. 우선순위는 처리 순서에만 사용하며, 근거가 부족한 주장도 결과에서 제외하지 않는다. |
| R-04 | 주장별 결과에 주장 원문, 발언 위치, 판정 근거와 원문 출처를 함께 보여준다. | MVP 필수. 근거와 일치·불일치 판정에는 근거 출처를 최소 1개 제공한다. 근거 부족은 예외로 처리한다. |
| R-05 | 주장별 판정을 `근거와 일치`, `근거와 불일치`, `근거 부족`으로 표시한다. | MVP 필수. 근거 부족 사유와 충돌 자료를 표시하며 숫자 점수는 제공하지 않는다. |
| R-06 | 얼굴 합성·변형과 영상 전체 AI 생성 결과를 구분하고 조작 가능성으로 안내한다. | `조작 의심`, `뚜렷한 조작 징후 없음`, `판단 보류`, `분석 불가`의 네 단계로 표시한다. |
| R-07 | 한 번에 YouTube Shorts URL 한 건을 분석한다. | 여러 영상의 일괄 분석은 MVP에서 제외한다. |
| R-08 | 결과마다 분석 ID와 분석 시각을 표시한다. | Google Form 피드백·신고에 분석 ID를 첨부하도록 안내한다. |
| R-09 | 같은 영상의 유효한 캐시 결과가 있으면 먼저 반환할 수 있다. | 캐시 결과임을 알리고 `다시 분석` 기능을 제공한다. 유효기간과 저장 기간은 처리 시간·비용 기준에서 정한다. |
| R-10 | 일부 분석을 수행하지 못해도 가능한 나머지 분석을 계속하고 완료된 결과를 제공한다. | 부분 성공은 `completed_with_limitations`, 시간 초과는 `timed_out`, 결과 없음은 `failed`로 구분한다. |

## 주장 선정과 처리 순서

지원 주제는 제한하지 않는다. 영상에서 인물·기관·날짜·수치·사건처럼 사실 여부를 외부 근거와 비교할 수 있는 주장을 모두 추출한다. 의견, 감상, 질문처럼 사실 판정이 불가능한 문장은 검증 대상에서 제외한다. 같은 의미를 다른 표현으로 반복한 주장은 하나로 합치고, 각 발언 위치와 반복 횟수를 함께 보관한다.

검증 대상은 다음 순서로 처리한다. 우선순위는 처리 순서에만 사용하며, 낮은 순위의 주장도 생략하지 않는다.

1. 영상 제목과 전체 내용에서 핵심 주제로 판단되는 주장
2. 영상에서 반복해서 언급된 주장
3. 인물, 기관, 날짜, 수치와 사건이 구체적으로 포함된 주장
4. 앞의 조건이 같을 때 영상에서 먼저 등장한 주장

검색 결과가 없거나 판정에 필요한 근거가 부족해도 해당 주장을 결과에서 제외하지 않고 `근거 부족`으로 반환한다.

## MVP 제외 범위

1차 MVP는 로그인과 회원가입 없이 YouTube Shorts URL을 한 번에 한 건씩 분석한다. 영상 파일 직접 업로드와 TikTok·Instagram Reels 등 YouTube 이외 플랫폼은 지원하지 않는다. 계정별 분석 이력, 여러 영상 일괄 분석과 관리자 화면도 구현하지 않는다. 사용자가 분석 결과를 직접 수정하는 기능은 제공하지 않는다.

분석 결과를 PDF나 이미지로 내보내는 기능은 1차 MVP에서 제외한다. 분석 결과를 공유하거나 보관하는 요구를 확인한 뒤 개발할 수 있는 후속 기능으로 남긴다.

사용자 피드백과 잘못된 분석 결과 신고는 하나의 Google Form으로 연결한다. 결과 화면에 분석 ID를 표시하고, 신고할 때 해당 값을 첨부하도록 안내한다.

같은 영상의 반복 요청에는 YouTube 영상 ID와 분석 파이프라인 버전을 기준으로 저장한 분석 결과를 재사용할 수 있다. 캐시 결과에는 분석 시각을 표시하고, 사용자가 `다시 분석`을 선택하면 캐시를 무시한다. 결과를 반환하기 전에는 영상이 여전히 공개 상태이며 삭제되지 않았는지 확인한다. YouTube는 새 영상으로 교체할 때 새 URL을 발급하지만, 기존 URL을 유지하면서 영상의 일부를 자르거나 흐리게 하고 오디오를 바꿀 수 있다. 따라서 영상 ID만 믿고 분석 결과를 무기한 재사용하지 않는다. 캐시 유효기간과 저장 기간은 처리 시간·비용 기준에서 결정한다. 관련 제약은 [YouTube 영상 교체 안내](https://support.google.com/youtube/answer/55770?hl=en-GB)와 [YouTube 영상 자르기 안내](https://support.google.com/youtube/answer/9057455?hl=en-GB)를 따른다.

## 처리 시간과 비용 기준

분석 요청을 접수하면 2초 이내에 진행 화면을 표시하고, 분석 시작 후 1분 이내에 우선순위가 높은 첫 번째 주장 검증 결과를 제공하는 것을 잠정 목표로 한다. 전체 분석은 5분 이내 완료를 목표로 하며 5분을 넘겨도 최대 10분까지 처리를 계속한다. 10분을 초과하면 처리를 종료하고 이미 완료된 결과는 제공하며, 끝나지 않은 주장은 `시간 초과`로 표시한다.

이 수치는 성능 측정 전의 잠정 목표다. 2026년 9월 8일 공유할 `evaluations`에서 미디어 조작 모델의 실행 시간을 확인하고, API 연동 후 전체 파이프라인을 측정해 조정한다. `evaluations`에 모델 실행 시간만 포함된 경우 이를 전체 처리 시간으로 보지 않는다. 영상 다운로드, 프레임·음성 전처리, 음성 인식, 미디어 조작 탐지, 주장 추출, 주장별 근거 검색·판정, 첫 결과 반환과 전체 결과 반환 시간을 각각 측정한다.

사용자에게는 대기 중, 분석 중, 일부 결과 확인 가능, 완료, 실패와 시간 초과 상태를 구분해 표시한다. 대기열에서 기다린 시간과 실제 분석 시간을 구분하며, 최대 10분은 실제 분석이 시작된 시점부터 계산한다. 상태 전환과 실행 기준은 [분석 실행 구조와 확장 기준](../design/analysis-runtime.md)을 따른다.

요청당 비용 한도, 구체적인 실행 장비, 분석 결과 캐시의 유효기간과 저장 기간은 추가로 결정한다.

## MVP 완료와 검수 기준

### 데모 영상 구성

1차 데모는 다음 조건과 유형을 기준으로 구성한다.

- 길이 2분 이내
- 공개 상태
- 주 사용 언어가 한국어인 YouTube Shorts
- 조작 또는 허위 정보 여부와 근거가 이미 알려진 영상
- 얼굴 합성·변형 영상
- 영상 전체가 AI로 생성된 영상
- 조작되지 않은 비교 영상
- 거짓 주장이 포함된 영상
- 사실인 주장이 포함된 비교 영상
- 얼굴이 없지만 검증 가능한 주장이 포함된 영상

영상 한 건이 여러 유형을 충족할 수 있다. 구체적인 영상과 수량은 조정준 팀장과 나정균 팀원이 1차 테스트 전에 정한다.

### 기대값 고정

각 데모 영상의 테스트 점검표에는 다음 값을 미리 기록한다.

- 영상 URL과 길이
- 공개 상태와 주 사용 언어
- 미디어 조작 유형
- 미디어 조작 기대 판정
- 반드시 추출해야 할 핵심 주장
- 주장별 기대 판정
- 기대 판정의 근거 출처
- 얼굴 유무
- 예상되는 정상 예외 상태

사전에 기대값을 정하지 않은 모호한 주장은 정확성 실패 판정에 사용하지 않는다.

정확성은 처리 완성도보다 먼저 확인한다. 다음 중 하나라도 발생하면 해당 데모 영상의 정확성 검수를 실패로 처리한다.

1. 조작된 영상을 조작되지 않은 것으로 판정한다.
2. 조작되지 않은 영상을 조작된 것으로 판정한다.
3. 거짓 주장을 사실로 판정하거나 사실인 주장을 거짓으로 판정한다.
4. 출처의 실제 내용과 다른 근거를 제시한다.
5. 다른 주장이나 다른 시점의 자료를 근거로 연결한다.
6. 분석할 수 없는 항목을 판정에 성공한 것처럼 표시한다.

`근거 부족`은 제품에서 정상적으로 제공할 수 있는 결과다. 관련 자료가 없거나 주장을 지지·반박하기에 근거의 관련성·신뢰성·시점이 충분하지 않으면 거짓으로 단정하지 않고 `근거 부족`으로 표시한다. 다만 테스트 점검표에 기대 근거가 있는 주장인데 시스템이 이를 확보하지 못하면 해당 필수 결과를 미완료로 계산한다.

지원 조건을 만족하지 않는 영상의 수집 실패는 정상적인 입력 거절이다. 데모 영상으로 확정한 공개 영상의 수집 실패는 검수 실패다. 얼굴이 없는 영상은 전체 실패로 처리하지 않는다. 미디어 영역에 `얼굴 기반 분석 불가`를 표시하고 주장 검증을 계속한다.

처리 완성도는 정상적으로 반환한 필수 결과 수를 테스트 점검표에 정의한 전체 필수 결과 수로 나눈 백분율이다. 시간 초과나 기대 근거를 찾지 못해 끝내지 못한 필수 결과는 미완료로 계산한다.

| 등급 | 처리 완성도 |
| --- | --- |
| A | 90 ~ 100 |
| B | 80 ~ 89 |
| C | 70 ~ 79 |
| D | 60 ~ 69 |
| F | 0 ~ 59 |

MVP 성공은 모든 데모 영상이 정확성 기준을 통과하고, 전체 테스트 점검표의 처리 완성도가 C 이상인 경우로 정한다. 데모 영상 중 아무 결과도 반환하지 못한 영상이 있으면 처리 완성도와 관계없이 실패한다. 등급은 내부 검수에만 사용한다. 사용자 화면에는 등급 대신 완료한 항목 수와 전체 항목 수를 표시한다.

처리 시간 검수에서는 `다시 분석`으로 캐시를 우회한다. 캐시 응답 시간은 별도로 측정한다. 같은 데모 목록을 동일한 실행 환경에서 반복해 판정과 처리 시간의 변동을 확인하며, 반복 횟수는 실행 비용과 환경을 확인한 뒤 정한다.

## 결과 표시 방향

분석 중에는 완료된 주장별 전체 분석 결과와 미디어 조작 결과를 순차 제공한다. 주장 추출과 중복 병합이 끝나면 모든 주장 카드를 먼저 만들고, 우선순위에 따른 처리 상태와 완료 진행률을 표시한다. 전체 작업이 완료되거나 10분 시간 초과로 종료되면 누적된 결과를 바탕으로 최종 요약을 제공한다. 상세 화면 흐름은 [분석 진행과 결과 UI](../design/result-ui.md)를 따른다.

주장별 전체 분석 결과는 사용자에게 제공하기로 한 주장, 판정, 발언 위치, 근거와 출처를 뜻한다. 모델의 원시 응답은 사용자 화면에 제공하지 않는다. 영상 전체 발언문을 제공할지는 별도로 결정한다.

사용자가 왜 영상을 의심해야 하는지, 어떤 발언이 문제인지, 근거가 무엇인지 이해할 수 있도록 주장별 판정을 `근거와 일치`, `근거와 불일치`, `근거 부족`으로 표시한다. 처리 상태인 대기 중·검증 중·완료·실패·시간 초과와 검증 판정을 구분한다.

모든 주장 카드에 주장 원문과 영상 속 발언 위치를 표시한다. 일정 구간에 걸친 발언은 시작·종료 시점을 표시하고 해당 위치로 이동할 수 있게 한다. 음성 인식으로 추출한 발언임을 구분하며, 정확한 위치를 확보하지 못하면 `약 00:18` 또는 `발언 위치 확인 불가`처럼 한계를 표시한다.

`근거와 일치`·`근거와 불일치` 판정에는 판정 근거와 원문 출처를 최소 1개 제공한다. 출처에는 자료 제목, 발행 기관·언론사, 발행일, 원문 링크와 해당 자료가 주장을 지지하거나 반박하는 이유를 포함한다. 정부·공공기관 원문, 언론 보도와 기존 팩트체크 등 출처 유형을 사용자가 구분할 수 있게 한다.

`근거 부족`에는 출처를 필수로 요구하지 않는다. 관련 자료가 없거나 관련성·시점이 맞지 않거나 출처끼리 충돌해 판정하지 못한 이유를 표시한다. 확보했지만 판정에 충분하지 않은 자료가 있으면 참고 자료로 제공하고, 자료를 찾지 못했으면 출처를 임의로 만들지 않는다.

출처가 충돌하면 어느 한쪽을 임의로 선택하지 않고 `근거 부족`으로 표시하며 서로 다른 자료와 내용을 함께 제공한다. 영상에서 검증 가능한 주장을 찾지 못하면 개별 주장 판정을 만들지 않고 `영상에서 외부 근거로 확인할 수 있는 주장을 찾지 못했습니다.`라고 안내한다.

주장 사실성 판정의 확률이나 숫자 점수는 MVP에서 표시하지 않는다. 판정별 색상과 세부 문구는 UI 시안에서 정한다.

## 실패와 부분 결과

미디어 조작의 각 탐지와 주장 사실성 검증은 가능한 범위에서 독립적으로 계속한다. 일부 분석을 수행하지 못했지만 제공할 결과가 있으면 `completed_with_limitations`로 종료하고, 완료된 결과와 분석하지 못한 영역·이유를 함께 표시한다. 분석 시작 후 10분을 초과하면 `timed_out`, 사용자에게 제공할 결과를 하나도 만들지 못하면 `failed`로 종료한다. 분석 중 일부 결과가 도착한 `partially_completed`와 일부 결과만 남기고 끝난 `completed_with_limitations`를 구분한다.

지원하지 않는 URL, Shorts가 아닌 영상, 일부 공개·비공개·연령 제한 영상은 분석을 시작하지 않고 지원 조건을 안내한다. 데모 대상으로 확정한 공개 영상의 수집 실패는 검수 실패로 처리한다.

얼굴을 찾지 못하거나 얼굴 탐지 모델이 실패해도 영상 전체 AI 생성 탐지와 주장 검증은 가능한 범위에서 계속한다. MVP의 발언 텍스트는 음성 인식으로 생성한다. 음성 인식을 사용할 수 없으면 미디어 분석만 계속하며 주장 사실성 검증을 `분석 불가`로 표시한다. 개별 주장 검증 실패는 해당 카드에만 표시하고 나머지 주장을 계속 처리한다. `근거 부족`과 `검증할 주장 없음`은 시스템 실패로 처리하지 않는다.

영상 다운로드 실패, 외부 API 응답 실패, 모델 실행 오류와 시간 초과처럼 재실행으로 해결될 가능성이 있는 경우에는 `다시 분석` 기능을 제공한다. 지원하지 않는 입력이나 검증할 주장 없음처럼 재실행해도 같은 결과가 예상되는 경우에는 다시 분석을 강조하지 않는다. 화면에는 기술 오류 코드 대신 사용자가 이해할 수 있는 실패 이유와 영향을 받은 범위를 표시하고, 내부 오류는 분석 ID로 추적한다.

## MVP 범위와 성공 기준

두 분석을 제공하는 서비스 방향과 YouTube Shorts 지원 대상을 정했다. 그 밖의 세부 범위와 완료 기준은 아래와 같다. 개발·제출 일정은 [프로젝트 계획](project-plan.md)을 참조한다.

| 확인 항목     | 현재 상태                                                      |
| --------- | ---------------------------------------------------------- |
| 지원 영상     | 주 사용 언어가 한국어이고 공개 상태가 `public`인 YouTube Shorts를 지원한다. 일부 공개·비공개·연령 제한 영상은 제외한다. [YouTube 공식 기준](https://support.google.com/youtube/answer/15424877)에 따라 현재 최대 3분까지 지원한다. |
| 조작 탐지 범위  | 얼굴 합성·변형과 영상 전체 AI 생성을 포함한다. 음성 합성은 제외한다. 모델별 실제 탐지 범위와 성능은 평가 결과를 확인한다.                                  |
| 주장 검증 범위  | 주제를 제한하지 않고 검증 가능한 주장을 모두 처리한다. 같은 의미의 주장은 합치고, 핵심 주제 관련성·반복 횟수·구체성·등장 순서로 우선순위를 정한다.                                |
| 처리 시간과 비용 | 첫 주장 결과 1분 이내, 전체 완료 5분 이내를 잠정 목표로 하며 최대 10분까지 처리한다. 단계별 성능 측정 후 조정한다. 요청당 비용·구체적인 실행 장비와 캐시 기간은 TODO다. |
| 실패·부분 결과  | 가능한 분석은 독립적으로 계속한다. 일부 결과가 있으면 `completed_with_limitations`, 10분 초과는 `timed_out`, 결과가 없으면 `failed`로 종료한다. 근거 부족과 검증할 주장 없음은 시스템 실패가 아니다. |
| 완료·성공 기준  | 모든 데모 영상이 정확성 기준을 통과하고 전체 처리 완성도가 C 이상이어야 한다. 데모 영상 선정, 기대값 점검표와 반복 횟수는 1차 테스트 전에 정한다. |
| 제외 범위     | 직접 업로드, 다른 영상 플랫폼, 로그인·회원가입, 계정별 이력, 일괄 분석, 관리자 화면과 사용자 결과 수정 기능을 제외한다. PDF·이미지 결과 내보내기는 후속 개발 후보로 남긴다. 피드백·신고는 Google Form으로 받는다. |
