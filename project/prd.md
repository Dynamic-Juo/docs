# Conan AI (가제) 제품 요구사항

- 상태: `Draft`
- 기획 담당: 조정준 팀장
- 관련 문서: [킥오프 회의록](../meetings/2026-09-03-kickoff.md), [AI 파이프라인](../design/ai-pipeline.md)

## 문서의 기준

서비스 구상과 1차 기획·기술 조사 자료를 바탕으로 구체화하여 작성했으며, 기획 검토에 따라 내용을 갱신 중이다. AI 모델 선정과 성능·신뢰도 검증은 나정균 팀원이 별도로 진행 중이며, 결과에 따라 관련 요구사항을 보완한다.

요구사항에는 현재 결정 상태와 추가 협의할 내용을 기록한다. `미정`은 결정되지 않은 항목, `보류`는 논의를 미루기로 한 항목, `상세 협의 필요`는 구체적인 범위나 방식을 논의할 항목이다. 사용자 가설은 요구사항의 결정 상태와 구분하며, 문서는 구체화하는 동안 `Draft`로 관리한다.

## 문제와 서비스 목적

기본 방향은 영상 URL을 입력하면 딥페이크 등 미디어 조작 가능성과 영상 속 주장의 사실성을 분석해 알려주는 서비스다. 고령층이 의심스러운 영상 정보를 판단할 때 도움을 주는 것을 목적으로 한다.

기획자는 부모가 허위 영상 정보에 속을 수 있다는 개인적인 걱정에서 이 아이디어를 제안했다. 고령층과 젊은 세대의 판별 능력 차이, 실제 수요와 이용 의향은 아직 확인되지 않은 사용자 가설이다.

## 목표 사용자와 유입 가설

부모와 자녀 모두 직접 사용할 수 있다. 누가 사용하든 영상 URL을 입력하고 분석 결과를 확인하는 흐름은 같다. 기술에 익숙하지 않은 사용자도 이해할 수 있는 단순한 사용 흐름을 지향한다.

자녀는 부모가 영상 정보에 속을까 봐 걱정해 서비스의 필요성을 느낄 수 있다. 부모가 스스로 검증 필요성을 느끼고 서비스를 찾는 경우보다 자녀가 먼저 찾아볼 가능성이 높다는 것이 현재 유입 가설이다. 기획자의 개인적인 경험에서 출발한 가설이며, 실제 유입 비중은 검증되지 않았다.

자녀가 직접 사용하거나 부모에게 소개할 수 있지만, 부모에게 소개하는 것을 서비스 사용의 필수 단계로 두지 않는다.

## 핵심 분석 경계

미디어 조작 가능성과 주장 사실성은 구분해서 제공한다. 실제 영상에도 허위 주장이 포함될 수 있고, AI로 생성된 영상의 발언이 사실일 수도 있으므로 두 결과를 하나의 진위 판정으로 취급하지 않는다.

| 분석        | 기본 방향                 | 미정인 범위                                   |
| --------- | --------------------- | ---------------------------------------- |
| 미디어 조작 탐지 | 영상의 조작 가능성을 분석한다.     | 얼굴 합성, 음성 합성, 전체 AI 생성 영상 중 MVP에서 지원할 대상 |
| 주장 사실성 검증 | 영상 속 정보를 외부 근거와 비교한다. | 지원 주제, 검증할 주장 수, 판단 기준                   |

## 사용자 시나리오

부모와 자녀에게 공통으로 적용되는 기본 흐름이다. 발언 위치와 근거 확인 기능의 포함 여부는 미정이다.

1. 사용자가 확인하고 싶은 영상의 URL을 입력한다.
2. 서비스가 영상을 분석한다.
3. 사용자가 미디어 조작 가능성과 주장 사실성 결과를 확인한다.
4. 사용자가 관련 발언 위치와 근거를 확인한다. (포함 여부 미정)

1차 제공 형태는 웹을 우선 고려하며, 이후 확장 시 웹앱 형태를 고려한다. 사용자는 영상의 공유 기능으로 링크를 복사한 뒤 서비스의 URL 입력란에 붙여넣는다.

## 요구사항 초안

| 번호 | 내용 | 상태 및 협의할 내용 |
| --- | --- | --- |
| R-01 | 영상 URL을 입력받는다. | 기본 방향 확정. 지원할 영상의 길이·언어·유형은 상세 협의 필요 |
| R-02 | 미디어 조작 가능성과 주장 사실성 결과를 분리해 보여준다. | 기본 방향 확정 |
| R-03 | 영상에서 검증 가능한 주장을 추출하고 외부 근거와 비교한다. | 상세 협의 필요: 주장 선정과 비교 방식 |
| R-04 | 주장별 결과에 발언 위치와 근거 출처를 함께 보여준다. | 미정: 기능 포함 여부 |
| R-05 | 근거가 부족한 경우 확인할 수 없다는 결과를 제공한다. | 미정: 기능 포함 여부, 표시 문구와 판정 조건 |
| R-06 | 조작 탐지 결과를 확정적인 단정으로 표시하지 않고 가능성으로 안내한다. | 미정: 안내 방식, 표시 단계와 기준 |

## 결과 표시 방향

사용자가 왜 영상을 의심해야 하는지, 어떤 발언이 문제인지, 근거가 무엇인지 이해할 수 있도록 설명하는 방식은 상세 협의가 필요하다. 주장별 결과를 지지·반박·근거 부족으로 구분할지는 미정이다.

구체적인 문구, 색상과 점수 표시 여부는 미정이다.

## MVP 범위와 성공 기준

두 분석을 제공하는 서비스 방향은 정했으나, 아래의 세부 범위와 완료 기준은 아직 합의하지 않았다. 개발·제출 일정은 킥오프 회의록을 참조한다.

| 확인 항목     | 현재 상태                                                      |
| --------- | ---------------------------------------------------------- |
| 지원 영상     | YouTube 중심의 구상. 영상 길이, 언어, 공개 범위, Shorts·라이브 지원 여부는 TODO다. |
| 조작 탐지 범위  | 모델 테스트 결과를 확인한 뒤 결정해야 한다.                                  |
| 주장 검증 범위  | 주제, 영상당 주장 수와 선정 기준은 TODO다.                                |
| 처리 시간과 비용 | 목표 대기 시간, 실행 환경과 비용 한도는 TODO다.                             |
| 실패·부분 결과  | 수집 실패, 얼굴 없음, 인식 실패, 근거 부족 시 사용자 안내는 TODO다.                |
| 완료·성공 기준  | 데모 대상 영상, 평가 방법과 통과 기준은 TODO다.                             |
| 제외 범위     | 명시적으로 제외할 기능은 TODO다.                                       |

## 함께 검토할 사항

1. 두 분석을 모두 제공하되 MVP에서 각각 어디까지 지원할 것인가.
2. 발언 위치·근거 표시와 판단 불가 안내를 필수 요구사항으로 채택할 것인가.
3. 어떤 입력과 결과를 확인하면 MVP가 완성됐다고 판단할 것인가.
4. YouTube 영상의 상세 지원 범위를 어떻게 정할 것인가. 예: 영상 길이·언어 제한, Shorts·라이브 및 비공개·연령 제한 영상 지원 여부.
5. TODO: 음성 합성과 얼굴이 없는 AI 생성 영상에 대한 추가 기획을 진행한다. MVP 포함 여부, 지원 범위와 분석할 수 없는 경우의 안내 방식을 정한다. 탐지 경로는 [AI 파이프라인](../design/ai-pipeline.md)에서 구체화한다.

미디어 조작 탐지와 주장 사실성 검증 중 어느 쪽에 제품의 비중을 더 둘지는 미정이다.
