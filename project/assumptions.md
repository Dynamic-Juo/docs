## 문서 목적

프로젝트의 문제의식, 사용자와 초기 구현 방향을 정할 때 전제로 둔 가정을 기록한다. 아래 내용은 확인된 사실이나 MVP 요구사항·성공 기준이 아니다. 현재 범위와 설계의 배경을 설명하는 데 사용한다.

## 사용자와 문제 가정

### A-01. 영상 정보 판별의 어려움

고령층을 포함해 영상 정보의 진위를 직접 판단하기 어려운 사용자가 있을 것으로 가정한다. 기획자가 부모가 허위 영상 정보에 속을 수 있다고 걱정한 경험에서 출발했다. 세대별 판별 능력의 차이는 확인된 사실로 전제하지 않는다.

### A-02. 서비스 이용과 유입

영상 정보의 진위를 확인하려는 수요가 있으며 부모와 자녀가 모두 서비스를 사용할 수 있다고 가정한다. 자녀가 먼저 서비스를 발견해 부모에게 소개할 가능성도 초기 유입 경로로 본다. 실제 이용 의향과 유입 비중은 확인된 사실로 다루지 않는다.

## 범위 가정

### A-03. Shorts 우선 지원

현대인의 숏폼 콘텐츠 소비가 늘고 있다는 인식을 바탕으로 Shorts를 우선 지원 대상으로 삼는다. 1차 MVP에서는 짧은 영상으로 범위를 제한하면 영상 다운로드, 프레임·음성 전처리, 미디어 조작 탐지와 주장 검증에 걸리는 런타임을 관리하기 쉽다고 가정한다.

가짜뉴스 접촉에서 숏폼이 차지하는 비율이 높다는 주장을 범위 결정의 전제로 사용하지 않는다. 1차 범위는 숏폼 소비에 대한 인식과 제한된 개발 환경에서의 런타임을 함께 고려한 선택이다.

## 구현 가정

### A-04. 기존 기술 조합

초기 구현은 별도의 데이터 학습 없이 기존 모델, 오픈소스와 외부 API를 조합해 구성할 수 있고, 직접 학습하는 방식보다 구현 공수를 줄일 수 있다고 가정한다. 이 가정은 초기 구현 방식을 정하는 데만 사용한다. 모델의 성능·사양, MVP 완료 기준과 사용자에게 제공할 요구사항은 각 기준 문서와 평가 결과에서 별도로 정한다.
