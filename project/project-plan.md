## 작성 기준

역할, 개발·제출 일정과 진행 현황을 관리한다. 목표와 예상은 구분하며, 팀 검토 전까지 문서는 초안으로 관리한다.

일정과 진행 현황이 바뀌면 해당 항목과 문서 상단의 최종 업데이트일을 갱신한다. 회의록에는 당시의 논의와 결정을 보존한다. 제품 범위는 제품 요구사항에서, 모델 비교 결과는 `evaluations/`에서 관리한다.

## 작업과 진행도 공유

세부 작업 일정을 모두 미리 확정하지 않고 개별 작업 로그를 남긴다. 조정준 팀장과 나정균 팀원은 9월 12일까지 개발 진행도를 매일 간략하게 공유한다. 기존 일정의 조율이 필요하다고 판단하면 영향을 받는 작업과 예상 지연을 상대 팀원에게 사전에 알린다.

이 문서에는 주요 일정과 진행 현황을 반영하고, 평가 결과와 상세 기능 명세는 해당 문서를 링크한다.

## 9월 13일 리뷰 후속 작업

이 절은 #7의 리뷰 답변을 반영한 현재 작업 추적이다. 위 일정 표는 #9의 일정 수정과 함께 정리할 대상으로 남긴다. #9·#10은 열린 PR이므로 해당 변경을 병합 완료로 표시하지 않는다. Vercel에서 최종 결과까지 확인했다는 나정균 팀원의 보고는 연동 확인이며, M-08 품질 인수 완료와 구분한다.

다음 실행은 다음 순서로 진행한다. 기한이 합의되지 않은 항목의 날짜는 정하지 않는다.

1. #7의 과거 평가와 현재 구현 설명을 분리하고 #9·#10 병합 시 기준 문서의 겹치는 항목을 확인한다.
2. 배포 커밋·이미지·보호 설정·복구 계획을 맞춘다. 최신 원문 검증 조건으로 인해 구형 배포본보다 근거 부족이 늘 수 있음을 인수 기준에 명시한다.
3. 원문 확보 경로와 의미 대조 실패 사례를 검증한다. 검색 요약문을 원문으로 표시하거나 판정 조건을 낮춰 통과시키지 않는다.
4. #10의 영상별 기대값을 고정하고 동일 배포본에서 시간·비용·정확성·처리 완성도를 기록한다. 실패 유형을 근거로 프롬프트·검색·STT를 조정한다.
5. #9의 개별 재검증 계약을 구현·연동한다. 공개 이용 전환은 홈서버 경계·자원 제한·요청 보호 검증 후 별도 진행한다.
