## 작성 기준

역할, 개발·제출 일정과 진행 현황을 관리한다. 목표와 예상은 구분하며, 팀 검토 전까지 문서는 초안으로 관리한다.

일정과 진행 현황이 바뀌면 해당 항목과 문서 상단의 최종 업데이트일을 갱신한다. 회의록에는 당시의 논의와 결정을 보존한다. 제품 범위는 제품 요구사항에서, 모델 비교 결과는 `evaluations/`에서 관리한다.

## 역할

| 담당자 | 담당 영역 |

| 조정준 팀장 | 기획, 구조·AI 파이프라인 설계, 프런트엔드(FE), UI 구상과 시안 |
| 나정균 팀원 | AI 모델 선정·테스트, 평가 문서 작성, 백엔드(BE) |

연동, 데모 테스트, QA와 제출 준비는 각자의 담당 영역에 따라 함께 진행한다.

## 작업과 진행도 공유

세부 작업 일정을 모두 미리 확정하지 않고 개별 작업 로그를 남긴다. 조정준 팀장과 나정균 팀원은 개발 진행도를 매일 간략하게 공유한다. 기존 일정의 조율이 필요하다고 판단하면 영향을 받는 작업과 예상 지연을 상대 팀원에게 사전에 알린다.

이 문서에는 주요 일정과 진행 현황을 반영하고, 평가 결과와 상세 기능 명세는 해당 문서를 링크한다.

## 미결 사항과 일정 확인

제품 범위·UI(M-01 ~ M-08, U-01 ~ U-11)와 설계(T-01 ~ T-13)의 결정 및 검토 내역은 [MVP 검토 목록](mvp-review.md)에서 관리한다. 영상 분석 결과는 완료된 주장별 결과를 순차 제공하고 전체 완료나 시간 초과 후 최종 요약을 제공하기로 결정했다. 영상 전체 발언문은 제공하지 않는다. 개별 기술 검증의 기한은 별도로 정한다. 문제·사용자·범위와 초기 구현 방향의 전제는 [프로젝트 가정](assumptions.md)에서 관리한다. 일정과 운영 상태는 이 문서에서 관리한다.
