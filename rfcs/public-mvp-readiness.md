# 공개 MVP 준비를 위한 승인 요청

- 상태: `Draft`
- 기준일: 2026-09-11
- 최종 갱신: 2026-09-12, P-05 자막 본문·리뷰 정합성 확인 추가
- 근거: [중간 점검](../evaluations/2026-09-11-midpoint-review.md)
- 결정 상태: 전부 미승인. PRD·설계·일정 문서에는 반영하지 않았다.
- 승인 주체: 사용자 확인 후 기획 담당 조정준 팀장과 합의가 필요하다. 담당 배정과 결정 날짜는 미정이다.

## P-01 전체 AI 생성 탐지 약속

현재 R-06은 전체 AI 생성 탐지를 MVP에 포함하지만 구현은 자가표기 확인뿐이다. 지금 수정은 미구현 상태를 부분 완료로 드러내는 것이며 탐지 기능을 추가한 것이 아니다.

제안: 1차 공개에서는 전체 AI 생성 탐지를 후속으로 미루고 미지원 안내를 명시한다. 얼굴 분석도 검증한 모델 범위와 한계를 표시한다. 범위를 유지하려면 별도 모델 선정·라이선스·정답 세트 검증을 먼저 완료해야 한다. 범위 축소와 완료 기준 변경은 승인 없이는 하지 않는다.

## P-02 자가표기와 실제 모델 분석을 분리

현재 제목·설명의 딥페이크·AI·패러디 같은 단어가 두 미디어 축에 동시에 영향을 줄 수 있다. 설명 영상이나 부정 문장도 조작 증거로 오해될 여지가 있다.

제안: 자가표기를 종류별 참고 정보로 분리하고 모델 판정과 구분한다. 단어 출현만으로 얼굴 합성이나 전체 생성의 증거로 사용하지 않는다. 기존 판정 임계값·점수 결합과 UI 표현에 영향을 주므로 승인 후 별도 변경한다.

## P-03 전사 부족의 안내와 음악 영상

전사 3단어인 테스트의 입력 길이 비율 100%는 인식 정확도가 아니다. 이번에는 이 비율의 의미를 바로잡았으며 몇 단어 이하면 실패라는 임의 기준은 넣지 않았다.

제안: 언어·발화 시간·세그먼트·반복/환각 징후를 실제 정답 자료로 측정한 뒤 전사 부족 경고 기준을 정한다. 음악·노래 중심 영상을 계속 지원할지 여부도 이 근거로 결정한다. 음악을 자동 제외하거나 sparse 전사를 무조건 실패로 바꾸는 것은 기획 승인 전에는 하지 않는다.

## P-04 익명 공개의 비용·결과 보호

M-06의 로그인 없는 MVP를 유지하면서도 결과 접근과 비용 남용은 제한해야 한다. 본인이 입력한 session_id만으로 사용자 인증을 대신할 수 없다.

제안: 익명 세션의 서버 발급 접근 수단, 요청 빈도·대기 한도·요청별 모델 사용 상한, 결과·로그 보관 기간을 정한다. 회원가입은 추가하지 않는다. 공개 전에 접근 수단의 분실/만료, 다른 브라우저 결과 조회, 분석 ID 피드백 흐름을 함께 결정한다.

## P-05 자막 기본 정책의 본문·리뷰 정합성

2026-09-12에 [PR #7의 수동 CC 리뷰](https://github.com/Dynamic-Juo/docs/pull/7#discussion_r3958898775)를 확인했다. 기획 본문은 MVP 자막 미사용이지만 리뷰에는 직접 작성한 CC 자막 도입을 긍정적으로 검토한 의견과 발언 전문이 아닐 수 있다는 우려가 있다. 기존 배포 기록은 manual이며 중간 점검 코드 기본값은 off다.

확인 요청: STT 기본을 유지할지, 업로더 등록 CC를 우선 사용하고 없으면 STT를 사용할지 결정한다. 영상에 편집으로 입힌 글자를 OCR로 읽는 기능과 CC는 구분한다. 자동 생성 CC 사용이나 자막이 정확하다는 보증은 이 제안에 포함하지 않는다. 승인 전에는 기획 본문이나 서버 환경변수를 바꾸지 않는다.

## 승인 없이 진행할 수 있는 후속 구현

확정된 근거 정책을 지키는 원문 수집, 종료 가능한 worker 구조, 입력 지원조건 검증, 테스트 종료 격리와 오류 메시지 보호는 기획 범위 안의 구현 작업이다. 다만 실제 서버 실행·배포·외부 API 호출은 별도 승인이 필요하다.

## 추적

각 제안의 결정·담당·확인 시점은 아직 미정이다. 승인되면 project-plan의 미결 항목과 PRD·설계의 해당 항목을 함께 갱신한다. 현재는 사용자의 기획 수정 사전 승인 지시에 따라 이 제안서 안에서만 추적한다.
