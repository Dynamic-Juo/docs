## 결론

현재 코드는 내부 개발계 검증용이며 일반 사용자에게 공개할 준비가 완료되지 않았다. Docker 기동과 job의 completed는 판정 정확성이나 전체 기능 성공을 보장하지 않는다.

이번 수정은 원문 없는 확정 판정, 분류 실패의 정상 판정, 무제한 내부 작업 대기와 오류 노출처럼 코드로 재현한 결함을 줄인다. 모델의 실제 정확도 향상, 원문 수집 완성, 최대 10분에 실제 계산 중단, 공개 인증·남용 방지까지 해결한 것은 아니다.

기획의 확정 요구는 수정하지 않았다. 범위 축소·판정 신호 변경·품질 임계값은 [승인 요청 제안](../rfcs/public-mvp-readiness.md)에 분리했다. 사용자가 기획 변경에 사전 승인을 요구했으므로 project-plan의 일정·결정도 이번에 수정하지 않았다.

## 기획을 다시 읽고 정정한 사항

- PRD는 전체 문서 상태가 Draft이지만 R-01~R-10 표에 항목별 확정 상태가 있다. 문서 전체를 미정으로 취급하지 않는다.
- M-06은 로그인·회원가입 없는 MVP다. 공개를 위해 회원가입을 필수로 추가하는 것은 현재 기획과 다르다. 내부 개발계의 Cloudflare Access는 별도의 운영 보호 수단이다.
- T-02는 기본 STT, 자막은 명시적으로 선택할 수 있는 후속 확장이다. 코드·작업 복사본 Compose·환경 예시의 manual 기본값을 off로 바로잡았다. 실제 배포 환경 파일은 수정하지 않아 기존 값이 우선한다.
- R-06은 얼굴 합성·변형과 전체 AI 생성 두 축을 요구한다. 전체 AI 모델이 없다는 이유로 그 축을 완료 기준에서 몰래 제외할 수 없다.
- Accepted evidence-policy는 검색 제목·요약만으로 판정하지 말고 원문·출처·독립성을 확인하도록 요구한다. 판정 수를 늘리기 위해 이 기준을 낮추지 않는다.

## 임시 영상은 삭제되는가

파이프라인이 직접 만든 요청별 임시 폴더는 finally에서 삭제한다. 성공·다운로드 실패·예상 밖 오류에서 삭제하는 모의 테스트를 추가했다. 폴더 삭제가 실패하면 로그와 `stages.cleanup`에 남기고, 반환 가능한 분석은 부분 완료로 표시한다. 삭제 오류가 기존 분석 예외를 덮어쓰지 않는다.

명시적으로 workdir를 지정하거나 keep_workdir를 켠 개발자 실행은 보존한다. API 요청에는 이 옵션이 없다. SIGKILL, OOM, 호스트 종료처럼 finally가 실행되지 않는 상황의 찌꺼기는 자동 복구를 보장하지 않는다. 서버의 실제 잔여 파일은 승인 범위 밖이므로 조회하지 않았다. 모델 캐시와 메모리 job 결과는 임시 영상과 별개다.

## 프롬프트와 근거 판정

좋은 기반은 주장·문맥의 원문 대조, 발언 위치, 게시일을 사건일로 단정하지 않는 규칙, 출처 인용문 대조, 판정과 처리 상태의 분리다. 그러나 프롬프트에 원문 확인을 요구하는 것만으로 서버가 원문을 확보한 것은 아니다.

이번 점검에서는 기계적으로 확인할 수 있는 인용·출처 범위·출력 형식을 서버에서 강제하는 데 우선순위를 뒀다. 모든 인용이 검증된 원문에 있어야 하며, 확인된 1차 출처 또는 독립 출처 계보 두 개 이상을 요구한다. 이 신뢰 표시는 모델 출력으로 만들지 않는다. 고정 사례와 회귀 테스트는 실제 모델 정확도나 프롬프트 인젝션 방어의 일반 성능을 증명하지 않는다. 실제 LLM 호출과 비용 발생 테스트는 실행하지 않았다.

기존 프롬프트 v3의 합성 11사례 결과와 이번 수정 후 테스트 결과는 구분한다. 새 변경을 기존 11/11로 인증하지 않는다. 모델 판정 기준을 느슨하게 만들거나 실제 영상 기대값을 출력에 맞춰 고치지 않는다.

## 추가 코드·배포 구성 점검

- requirements는 대부분 최소 버전만 고정하고 Docker 기본 이미지·모델 revision/다운로드 checksum도 고정하지 않는다. 같은 Git 커밋의 재빌드가 같은 의존성·모델을 뜻하지 않는다. 검증된 이미지 digest 재사용은 보완책이며, lock·모델 무결성·SBOM/취약점 점검은 별도로 필요하다. 이번에 운영 설치 버전이나 CVE 안전성을 검증했다고 주장하지 않는다.
- 저장소 Dockerfile에는 비 root USER가 없고 모델 캐시는 `/root/.cache`다. 배포 Compose 예시는 CPU·메모리를 제한하고 host port를 비우지만, 이것만으로 비 root·최소 권한·읽기 전용 파일시스템·outbound 격리가 완성되지 않는다. 사용자/볼륨 권한을 검증하지 않고 변경하면 기동이 깨질 수 있어 이번에는 바꾸지 않았다.
- VLM/Ollama는 선택 기능이며 공개 요청에서 지정할 모델·프레임 수의 서버 정책이 부족하다. 비활성화 상태를 추정해서 안전하다고 단정하지 않으며 실제 env도 조회하지 않았다.
- Python 분석 함수를 스레드에서 실행하므로 600초가 넘어도 계산을 즉시 끊지 못하고 정상 종료도 오래 기다릴 수 있다. bounded queue 수정은 실행 시간 제한과 다른 문제다.
- API가 작업을 메모리에 저장하므로 프로세스 재시작 시 결과가 사라지고 다중 uvicorn worker는 맞지 않는다. 같은 맥미니의 개발·운영 분리는 가능하지만 CPU·메모리·호스트 장애는 공유한다.
- 진행 중 작업의 중복 제거 키는 URL뿐이다. 동일 영상에 서로 다른 모델·프레임·자막 옵션을 요청해도 첫 요청의 작업을 재사용한다. 옵션별 재사용 기준과 공개 요청의 서버 고정 옵션 정책을 함께 정리해야 하며 이번에 해결했다고 표시하지 않는다.
- `enforce_input_limits=False`는 다운로드 후 길이 재검사만 끈다. URL·공개/연령·다운로드 전 길이 경계는 항상 적용한다. 공개 요청으로 이 옵션을 넘길 수는 없다.

## 공개 전 남은 작업

1. 실제 중단 가능한 처리 프로세스, 다운로드 크기·임시 디스크 상한, 요청별 자원 사용 상한을 구현하고 부하 검증한다.
2. 원문 수집과 검증된 1차/독립 출처 정보를 확보한다. SSRF·응답 크기·본문 파싱·사이트 이용 조건도 함께 설계한다.
3. Shorts 분류·public·한국어 여부를 실제 응답에서 검증한다. watch 주소와 Shorts가 아닌 영상은 같은 개념이 아니다.
4. 익명 사용자별 요청 제한·결과 접근·보관/삭제 기준을 정한다. CORS는 인증이나 남용 방지 기능이 아니다.
5. 정답과 필수 주장이 고정된 실제 영상 세트로 미디어·전사·검색·판정의 품질과 시간/비용을 각각 측정한다.
6. Vercel의 고정 프론트 Origin, 개발계 팀원 Access, 쿠키·OPTIONS, 부분/실패 응답 계약을 함께 검증한다.
7. 변경 브랜치를 검토한 뒤에만 별도 승인으로 이미지 빌드·개발계 배포·키 포함 E2E를 실행한다. 일반 사용자 공개는 마지막 단계다.

## 외부 근거와 사용 조건

- [OWASP SSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html): 입력 allowlist뿐 아니라 리다이렉트·네트워크 경계도 검토해야 한다. 이번 URL 검사를 완전한 outbound 차단으로 표현하지 않는다.
- [yt-dlp YoutubeDL 구현](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/YoutubeDL.py): match_filter·TLS·extractor 설정을 확인했다. 코드 저장소의 라이선스와 YouTube 콘텐츠 이용 조건은 별도다. 현재 배포 버전 호환성과 서비스 이용 조건은 공개 전에 다시 확인한다.
- [사용 중인 분류기 모델 카드](https://huggingface.co/dima806/deepfake_vs_real_image_detection/blob/main/README.md): Apache-2.0 표기를 확인했다. 작성자가 데이터 시점 차이에 따른 concept drift를 경고한다. 모델 카드의 성적은 우리 영상·전처리·집계의 성적이 아니며 임계값을 그대로 낮추지 않았다.
