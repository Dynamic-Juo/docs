## 문서의 기준

조정준 팀장이 정리한 MVP 확정 사양의 결정 항목을 하나씩 실제 코드와 대조한 결과다. 상태는 실행해서 확인한 것만 `구현`으로 적고, 코드는 있으나 검증하지 않은 것과 일부만 만족하는 것은 `부분`으로 구분한다. 기준 문서 중 `mvp-review.md`는 아직 병합 전 초안(`docs/mvp-review` 브랜치)이므로, 확정 과정에서 항목이 바뀌면 이 점검도 다시 해야 한다.

## 제품 범위와 완료 기준

| ID | 결정 내용 | 상태 | 확인한 내용과 남은 것 |
| --- | --- | --- | --- |
| M-01 | 두 분석을 비슷한 비중으로 제공하되 주장 사실성 검증을 우선한다 | 부분 | 두 축을 분리해 모두 제공한다. 다만 실행 순서는 여전히 미디어 조작이 먼저이고 주장 검증이 나중이라, "우선한다"를 처리 순서로 해석한다면 반영되지 않았다. 결과 전달은 준비되는 대로 각각 나가므로 화면상 우선순위는 프런트에서 정할 수 있다 |
| M-02 | 한국어·공개 상태 YouTube Shorts(3분 이하)만 지원 | 미구현 | 현재 아무 YouTube URL이나 받는다. 길이·공개 범위·Shorts 여부를 확인하지 않는다. 지원 조건 밖 입력에 대한 거절 안내도 없다 |
| M-03 | 얼굴 합성·변형과 영상 전체 AI 생성을 탐지하고 음성 합성은 제외 | 부분 | 얼굴 합성·변형은 구현·검증했다. 음성 합성 신호(TTS)는 점수에서 제거했다. 영상 전체 AI 생성은 전용 모델이 없어 자가표기가 있을 때만 판정하고 나머지는 분석 불가로 응답한다(T-06 참조) |
| M-04 | 검증 가능한 주장을 모두 검증, 같은 의미는 병합하고 언급 위치 보관, 4개 기준으로 우선순위 | 부분 | 영상당 최대 5건 상한이 남아 있다. 중복은 병합이 아니라 후순위 후보를 버리는 방식이라 반복 언급 위치가 보존되지 않는다. 우선순위 기준도 문서의 4가지(핵심 주제 관련성·반복 횟수·구체성·등장 순서)와 다르게, 수치 포함 여부 점수와 구간 분산으로 정해진다 |
| M-05 | 반응형 웹을 PWA로 제공 | 해당 없음 | 프런트엔드 범위다 |
| M-06 | 로그인 없이 URL 한 건씩, 캐시 사용, Google Form 피드백 | 부분 | 로그인 없는 단건 분석은 그대로다. 진행 중인 같은 URL은 job을 재사용하지만, 완료된 결과를 영상 ID와 파이프라인 버전으로 캐시하는 기능은 없다 |
| M-07 | 첫 결과 1분·전체 5분·최대 10분, Worker 1건·GPU 1건·주장 3건 병렬, 세션당 1건 | 부분 | 최대 10분은 소프트 타임아웃으로 구현했다(진행 중인 단계를 강제로 끊지는 못한다). Worker 동시 실행 수 기본값은 3이라 문서의 1건과 다르다. 주장 검증은 순차 처리로 3건 병렬이 아니다. 세션당 활성 분석 1건 제한도 없다 |
| M-08 | 데모 영상 기대값을 고정한 점검표로 정확성·완성도 평가 | 미착수 | 데모 영상 목록과 기대값 점검표를 아직 만들지 않았다 |

## 결과 표시와 실패 안내

| ID | 결정 내용 | 상태 | 확인한 내용과 남은 것 |
| --- | --- | --- | --- |
| U-01 | 완료된 주장·미디어 결과를 순차 제공, 카드 먼저 생성, 종료 후 최종 요약 | 구현 | 주장 수가 확정되면 카드를 전부 대기 상태로 만들어 내보내고, 검증되는 대로 갱신한다. 미디어 조작 결과는 주장 검증을 기다리지 않는다. 실측 폴링에서 확인했다(4초 빈 결과 → 40초 두 축과 카드 혼재 → 44초 전체 완료) |
| U-02 | 주장 원문·발언 위치 필수, 판정 근거에 출처 정보와 판단 이유 | 부분 | 주장 원문·발언 위치·출처 제목·링크·발행일은 제공한다. 출처 유형과 "이 자료가 왜 주장을 지지·반박하는지"는 없다. 후자는 근거를 읽고 설명하는 단계가 필요해 현재 규칙 기반으로는 만들 수 없다 |
| U-03 | 판정을 `근거와 일치`·`근거와 불일치`·`근거 부족`으로, 근거 부족 사유 구분, 숫자 점수 미표시 | 부분 | 판정 세 종류는 있으나 이름이 다르다(`supported`/`refuted`/`unverified`, 화면 문구는 `지지`/`반박`/`판단 유보`). 근거 부족 사유는 문장으로만 전달하고 문서가 정한 다섯 가지(자료 없음·관련성 부족·시점 불일치·출처 충돌·신뢰성 부족)로 구분하지 않는다. 숫자 점수 미표시는 지켜진다 |
| U-04 | 얼굴 합성·변형과 영상 전체 AI 생성을 구분해 4단계로 표시, 단정 표현 금지 | 구현 | 두 축을 분리하고 `조작 의심`·`뚜렷한 조작 징후 없음`·`판단 보류`·`분석 불가` 네 단계로 응답한다. 연속 점수는 내부 신호로만 남긴다 |
| U-05 | `completed_with_limitations`·`timed_out`·`failed` 구분, 부분 실패에도 나머지 분석 계속 | 구현 | 작업 상태를 문서의 표대로 구현했다. 프레임을 못 뽑아도 주장 검증은 계속하고, 자막을 못 쓰면 음성 인식으로 대체한다 |

## 구현 방식과 기술 검증

| ID | 항목 | 상태 | 확인한 내용과 남은 것 |
| --- | --- | --- | --- |
| T-01 | 영상·음성·자막 수집 수단 | 부분 | yt-dlp로 영상·오디오·자막 수집을 여러 영상에서 실행 확인했다. 이용 조건과 라이선스는 확인하지 않았다(T-13과 함께 남은 과제) |

| T-04 | 딥페이크 모델 선정·평가 | 확인 완료 | [딥페이크 모델 비교](deepfake-detection-model-comparison.md)에 기록했다 |
| T-05 | 영상 전처리와 결과 집계 | 부분 | 얼굴 검출·crop 후 분류하고, 프레임 점수를 평균과 최댓값의 블렌드로 집계한다. 여러 얼굴이 등장할 때의 처리 기준은 정하지 않았다(현재 가장 큰 얼굴 하나만 사용) |

| T-07 | 주장 추출 모델과 출력 | 부분 | 규칙 기반으로 구현했다. LLM은 쓰지 않는다. 문맥을 넘는 주장(대명사로 지칭한 대상)은 놓치고, 수치가 없는 사실 주장도 놓친다 |
| T-08 | 한국어 근거 검색 수단 | 미결 | 현재 위키백과(한국어·영어)만 기본이다. 대안은 [팩트체크 방법론 대안](factcheck-method-options.md)에 정리했다 |
| T-09 | 검색 실행 순서 | 부분 | 전문 기관 판정을 먼저 조회하고 그다음 위키백과를 조회하도록 순서를 고정했다. 병렬 처리는 하지 않는다 |
| T-10 | 근거 선택·비교와 판단 유보 | 부분 | 주장의 핵심어가 근거 제목·인용문에 없으면 버리는 관련성 필터를 구현했다. 발표 시점 적합성 확인과 상충하는 자료 처리는 구현하지 않았다 |
| T-11 | 판정 모델(LLM·NLI) | 미도입 | 현재는 전문 기관의 공개 판정 표기를 옮기는 것 외에 판정 로직이 없다 |
| T-12 | 연동 데이터와 예외 처리 | 구현 | `jobId` 폴링, 작업 상태 전이, 구조화된 오류 응답을 구현했다. 재시도 정책은 없다 |
| T-13 | 기술·가중치·데이터 사용 조건 | 미확인 | yt-dlp, faster-whisper, MediaPipe, dima806 모델, 위키백과 API의 라이선스와 이용 조건을 아직 확인하지 않았다. **제출 전 반드시 확인해야 한다** |

## 지금 가장 부족한 것

우선순위 순으로 정리한다.

1. **영상 전체 AI 생성 탐지(T-06)**: MVP 포함으로 결정됐는데 탐지 경로 자체가 없다. 모델 후보를 정하고 얼굴 기반 탐지와 어떻게 연결할지 설계가 필요하다.
2. **팩트체크가 실질적으로 판정을 못 한다(T-08, T-11)**: 위키백과만으로는 판정 근거가 없어 모든 주장이 판단 유보로 끝난다. 전문 기관 판정 검색을 붙이거나, 근거를 읽고 판정하는 단계를 추가해야 한다.
3. **입력 조건 검증(M-02)**: Shorts·길이·공개 범위를 확인하지 않아 지원 범위 밖 영상도 그대로 분석한다.
4. **주장 처리 범위(M-04)**: 상한 5건, 중복 병합 없음, 우선순위 기준 불일치.
5. **라이선스 확인(T-13)**: 제출물에 들어가는 모든 구성 요소의 사용 조건이 미확인 상태다.
6. **완료 기준(M-08)**: 데모 영상과 기대값 점검표가 없어 "완성됐다"를 판단할 방법이 없다.
