# Conan AI (가제) 문서

이 저장소는 YouTube 영상의 미디어 조작 가능성과 영상 속 주장의 사실성을 분석하는 Conan AI (가제)의 기획, 설계, 검증 및 의사결정 기록을 관리한다.

프로젝트는 [Wanted AI Championship 2026](https://event.wanted.co.kr/ai-championship/2026) 출품을 목표로 진행한다.

현재 일정과 진행 현황은 [프로젝트 계획](project/project-plan.md)에서 확인한다. 추가 기획과 MVP 확정을 위한 논의 항목은 [MVP 검토 목록](project/mvp-review.md)에 모았다.

## 핵심 설계 경계

제품은 다음 두 분석 결과를 구분한다.

1. 미디어 조작 탐지: 영상이나 인물의 얼굴 및 음성이 합성되었을 가능성을 분석한다.
2. 주장 사실성 검증: 영상에서 검증 가능한 주장을 추출하고 외부 근거와 비교한다.

두 결과는 하나의 진위 판정으로 취급하지 않는다. 실제 인물이 등장한 영상에도 허위 주장이 포함될 수 있고, 합성된 영상의 발언 내용이 사실일 수도 있기 때문이다. 제품 표시 방식은 `prd.md`에서, 처리 방식은 `ai-pipeline.md`에서 정의한다.

## 문서 분리 기준

### 단일 파일로 유지하는 경우

- 같은 목적과 결론을 향하는 내용이다.
- 한 흐름으로 읽어야 문맥이 유지된다.
- 담당자와 변경 주기가 같다.
- 문서 전체에 하나의 상태를 부여할 수 있다.

초기 PRD, 프로젝트 계획, 시스템 개요, AI 파이프라인은 각각 단일 파일로 시작한다.

### 여러 파일로 분리하는 경우

다음 조건 중 두 개 이상에 해당하면 기존 문서를 분리한다.

- 서로 다른 담당자가 독립적으로 수정한다.
- 일부 내용만 별도의 검토나 승인이 필요하다.
- 변경 주기가 다른 내용이 한 파일에 섞여 있다.
- 개별 문서를 다른 문서에서 반복해서 참조한다.
- 하나의 상태로 관리할 수 없는 항목이 함께 들어 있다.
- 같은 형식의 기록이 계속 추가된다.

회의록과 ADR은 작성 시점과 상태가 각각 다르므로 처음부터 파일을 나눈다. 파일 길이는 보조 판단 기준으로만 사용한다.

## 필요할 때 추가하는 문서

다음 디렉터리는 현재 만들지 않는다. 각 생성 조건이 발생하면 첫 문서와 함께 추가한다.

| 디렉터리 | 생성 조건 | 파일 단위 |
| --- | --- | --- |
| `evaluations/` | Playground에서 모델, 오픈소스 또는 외부 API 비교 실험을 시작할 때 | 평가 주제 하나당 한 파일 |
| `rfcs/` | 여러 저장소나 담당자에게 영향을 주는 설계 변경에 사전 합의가 필요할 때 | 제안 하나당 한 파일 |
| `submission/` | 대회 제출 내용과 데모 시나리오를 조립하기 시작할 때 | 제출물 종류별 한 파일 |

실험 코드, 샘플 입력 및 실행 스크립트는 Playground 저장소에서 관리한다. `evaluations/`에는 실험 목적, 조건, 지표, 결과, 해석과 재현 경로를 기록한다.

## 브랜치 운영

- 작업 브랜치는 `main`에서 분기하며 `docs/<작업 주제>` 형식으로 이름을 짓는다.
- 작업 주제는 영문 소문자와 하이픈으로 작성한다. 예: `docs/initial-planning`, `docs/pr-workflow`.
- 하나의 브랜치와 PR에는 함께 검토할 변경만 포함하고, 커밋은 변경 목적별로 나눈다.
- 독립적인 PR은 같은 기준의 `main`에서 분기해 서로의 변경을 포함하지 않는다. 의존 관계가 있으면 PR에 명시한다.
- PR 생성 순서와 병합 순서는 구분한다. 독립적인 PR의 병합 순서는 검토 상황에 따라 정한다.

## 작성 규칙

- 저장소 전체의 상세 작성 규칙은 `AGENTS.md`를 따른다.
- 파일명은 영문 소문자와 하이픈을 사용한다.
- 회의록은 `YYYY-MM-DD-topic.md` 형식을 사용한다.
- ADR은 `NNN-decision-title.md` 형식을 사용한다.
- 문서 본문은 평서체로 통일한다.
- 코드 블록 내부를 제외하고 문서 요소 사이의 빈 줄은 한 줄만 사용하며, 편집 후 연속 빈 줄이 남지 않았는지 확인한다.
- 같은 내용을 여러 문서에 복사하지 않고 기준 문서를 링크한다.
- 사실, 결정, 가설과 미결 사항을 구분해서 작성한다.
- 수치에는 측정 조건이나 출처를 함께 기록한다.
- 외부 자료, 모델, API와 오픈소스에는 출처 및 라이선스를 기록한다.
- 문서 변경도 Pull Request에서 검토한다.

## 문서 상태

검토와 합의가 필요한 문서에는 문서 상단에 상태를 기록한다. 상태 라벨은 백틱으로 감싸며, `- 상태:` 뒤에 `Draft`와 같이 표기한다.

| 상태 | 의미 |
| --- | --- |
| `Draft` | 초안 작성 중이며 기준으로 사용하지 않는다. |
| `In Review` | 팀 검토 중이다. |
| `Accepted` | 팀이 합의한 현재 기준이다. |
| `Superseded` | 다른 문서나 결정으로 대체되었다. |

회의록과 평가 결과처럼 특정 시점의 사실을 기록하는 문서에는 상태를 생략할 수 있다.
